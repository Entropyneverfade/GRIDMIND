# GRIDMIND 阶段成果 / Stage report — 2026-10-14

## 0.2.4 全规划年阶段 / Full annual-source horizon

桌面规划方法新增“动态规划（全规划年）”，从基年之后连续读取每一个年度库；原“双年度”与单年GA仍可选。每年既有机组、负荷、外送、风光和水文分别取当年，终期候选位保持统一，年度独有计划项目按该年外生给定并逐年列入报表。Bellman、Gurobi和同口径GA均使用同一组逐年8760小时状态费用。The optional full-horizon mode extends the annual stage sequence while retaining the same state semantics and deterministic hourly engine.

阶段工作簿另有“逐年GA与DP”页和同名CSV，列出两种算法的每年状态、可行性、年度及折现费用；程序检查GA逐年折现费加总等于GA总目标。The per-year comparison makes a feasible heuristic gap traceable to specific planning stages.

批处理入口现可显式指定GA种群、代数和随机种子，运行清单存档这三个值；源码与EXE对照必须使用相同设置。The batch application records the GA controls so comparisons use the same input, search budget and seed.

公开合成测试给出三阶段已知最优路径 `(0,1,1)`，并通过三年度8760小时物理集成；单一负荷系数冒充完整年度序列会被拒绝。本地完整年度源库试算通过各阶段源工作簿哈希、逐时平衡、储能库存、水电月预算、年费、外生明细和Bellman/Gurobi费用复核。任何项目数值、逐时曲线、图片、源文件路径或输入哈希均未进入公开副本。A three-stage synthetic known answer and a local full-sequence physical audit support the feature; project-derived evidence stays private.

最终版本化EXE与源码在相同年度输入、成本快照及GA参数下得到完全相同的GA和DP路径及目标；四个年度均通过物理与费用门槛，应用另从该本地存档生成12张月图和5种缩放视图。项目图和逐时表仍只保存在本机。The packaged batch run matches the source implementation under identical settings; its project-derived images and hourly tables remain local.

## 0.2.3 中间年度外生计划项目 / Source-year-only projects

进一步核对年度清单发现：某个中间年度可能含有终期候选清单之外的计划增量。0.2.2会忽略这类机组，造成该年度供给与费用少计。0.2.3将它们作为**仅该年度的外生给定计划**，与同站存量合并容量及最低出力，年化资本费纳入阶段成本，并在运行清单发出警示；终期候选0/1位仍只控制终期项目。0.2.1/0.2.2“年度源库”模式的既有结果须重算。Version 0.2.3 includes source-year-only planned capacity and its annualized cost as an explicit exogenous input for that year; earlier source-mode archives require rerunning.

合成物理反例验证同站25 MW增量和1000元等年值均进入评价，逐时平衡不受损；公开的模型与物理合成测试32项，本地另有2项导出隐私门测试。This is a declared scenario assumption: making temporary projects themselves endogenous, with optional commissioning and retirement, remains future work. No project-derived values are published.

桌面工作簿新增仅在适用时出现的“年度外生计划”页及对应CSV，逐项记录外生容量和年化费用。应用批处理与源码运行在相同输入指纹下得到一致的阶段路径和费用；本地多组相邻年度输入均通过前后两年8760小时功率平衡、储能状态、月水电预算、费用和月份边界复核。公开仓库只记录这些验收门槛，不含项目数值、图片、逐时曲线或输入哈希。The desktop workbook now separately audits exogenous commitments; packaged and source runs agree on the same fingerprint, while all project-derived details stay local.

## 0.2.2 年度存量装机修正 / Annual existing-capacity correction

审计发现0.2.1的“年度源库”动态规划模式虽使用前一年的负荷与天气，却错误地沿用了终期既有装机。0.2.2改为每阶段从对应年度源库读取既有机组有效容量，仍以终期候选项目统一编码建设决策。**0.2.1年度源库模式生成的规划费用和路径应重新计算**；0.2.1合成系数情景案例不受此处年度存量对齐错误影响。An audit found that the source-input mode reused terminal existing capacities in the earlier stage. Version 0.2.2 corrects this; source-mode results from 0.2.1 must be rerun. The published controlled synthetic scaled case is unaffected by this specific alignment error.

新合成反例设前一年50 MW既有燃气、终期100 MW、全年75 MW负荷；修正后前一年缺供为25 MW×8760 h，终期缺供为0，逐时功率残差为0。合成测试增加到31项，并继续单独检查年度风光、水文和候选位身份。The counterexample checks a physical consequence, not just an object-field copy.

修正后的年度源库模式已在本机项目输入上重新运行并通过Gurobi路径一致性、8760小时功率平衡、储能状态和工作簿核查；项目费用、路径、源文件与其哈希只保留本地。The corrected project run passed local numerical gates, while all project-derived values remain private.

本段仅记录0.2.2当时的物理一致性门槛；后来发现源库独有项目遗漏，故这些年度源库结果已归档失效。Physical residual checks alone did not detect the omitted source-year-only plants; those local outputs were invalidated after the 0.2.3 audit.

## 0.2.1 年度阶段输入与同算例对照 / Annual inputs and paired comparison

双年度动态规划默认使用各年度源库的负荷、外送、风光和水文曲线，终期候选项目仍采用共同身份、设计容量与位序。源库里预列的候选容量仍由规划状态决定投运；缺失年度可再生曲线时显式报错。原“负荷系数情景”保留为可选项，并在阶段工作簿和审计清单中标明。The default source mode uses separate annual operating profiles with a common terminal project encoding; the optional scaled scenario is explicitly labeled.

DP 存档同时用相同的年度状态费用表执行多年度 GA 对照，单独保存 GA/DP 对比表及 GA 逐代记录；规划窗口增加 GA 可行收敛曲线和 DP/Gurobi 下界。GA 未找到可行解时不计算虚假的最优差距。A paired GA run queries the already computed stage-cost tables, so the comparison shares the same 8,760-hour evaluations and feasibility rules.

新增的年度风光/水文曲线对齐、缺失曲线拒绝和对照归档测试使合成测试达到 30 项。New synthetic tests bring the suite to 30 checks. Project-derived annual inputs and outputs remain local and are excluded from the public release.

版本化 Windows EXE 的后台窗口初始化、内置 Gurobi 路径检查、完整合成双年度批处理均返回成功；年度源库模式另在本机项目批处理中通过8760小时与储能守恒核验，具体项目输入和派生结果没有进入仓库。The versioned EXE passed its startup, solver and synthetic end-to-end checks. A private local project run tested the source-input path; no project data or derived values are published.

## 0.2.0 完整合成规划与动态规划 / Complete synthetic planning and DP

公开合成八类机组、八个候选项目的单年度 GA 案例已生成 8,760 小时主表、逐站储能表、Origin 原生图和一个合并工作簿。GA 用固定种子找到只增加 15 MW 燃气的方案，年费用 138,077,847.65 元；全部 256 个染色体的穷举审计得到同一最优方案。The synthetic single-year GA result matches an exhaustive eight-bit audit.

依据原教学PPT的“规划年—投运状态—决策—阶段费用—递推”结构，新增两个年度阶段的 Bellman 动态规划，Gurobi 以独立0/1状态模型核验。相同合成案例的双年度 GA 和 DP 共用全部阶段运行费用表，均选择状态 (0,2)，折现总费用 235,408,583.30 元，差距 0%。两个阶段的最大逐时功率平衡残差分别约 1.60e-14、2.84e-14 MW。The numerical comparison is only for this finite synthetic instance.

合成最终年结果另导出12张自然月图，每月标注真实事件；本案例没有缺供或备用缺口，因此标净负荷峰值日与最大弃电日。完整图见 [月图集 / Monthly gallery](MONTHLY_GALLERY.md)，单年度与双年度结果、分章分析见 [完整案例 / Case study](CASE_STUDY.md)。详细操作见 [使用说明 / User guide](USER_GUIDE.md)，未来功能见 [开发计划 / Roadmap](ROADMAP.md)。

## 已验证能力 / Verified capabilities

GRIDMIND 已提供带原创图标的 Windows 单文件应用、可重新打开存档的日/周/月/年和任意时段窗口、八类机组的确定性 8760 小时运行、跨日储能库存、遗传规划、合并表格及分图保存。桌面窗口与批处理共用计算入口。The Windows single-file application, archived-run viewer, eight-technology chronological simulation, continuous storage state, genetic planning, consolidated workbook and separate figure folders have been exercised through the same calculation entry point.

本轮增加了完全合成的八类机组演示，负荷、风电、光伏分别用固定种子生成非重复扰动。正式EXE由同一窗口绘图函数导出日、周、月、年及任意小时视图；窗口现为单张堆叠图，洋红负荷线加粗，弃风光使用对应颜色斜线。The demo profiles are independently synthetic and seed-reproducible. The EXE exports five zoom views through the viewer's own drawing function. The same chart combines source output, negative storage charging and a prominent load trace.

本阶段修正了常规水电月水量边界：月预算只限制可用发电量；当整月正净负荷为零时，目标出力为零，剩余水量留在“未用预算”口径。This stage treats the monthly hydro budget as an upper bound. Zero positive net load yields zero scheduled hydro, and unused water is retained as a diagnostic instead of forced generation.

随后统一了闰年的8760小时时间轴：兼容输入省略2月29日，导入器核对日期标签，月水量、逐月表及交互窗口均按365日规划年分段。A compatible leap-year input omits February 29; the importer checks day labels, and hydro, monthly tables and the viewer share the same 365-day boundaries.

## 模型边界 / Model limits

当前采用单区域铜板、确定性缺供、试算成本、月水量近似、逐日开机及逐时经济顺序规则。尚未实现线路潮流、概率 EENS/LOLE、完整级联水力模型或全年全局最优机组组合。The model is a deterministic single-region baseline with approximate hydro and commitment rules. It does not claim network flow, probabilistic adequacy, cascade hydraulics or globally optimal annual unit commitment.

外部项目输入、逐时结果、表格和项目图只保存在用户本机，公开仓库只有源代码、合成测试、合成展示图、原创图标与数学推导。External project inputs and derived results remain local; the public repository contains code, synthetic tests and preview, icon and mathematical documentation only.
